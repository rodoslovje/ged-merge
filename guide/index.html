GED Merge User's Guide

A GEDCOM file (.ged) is the standard format genealogy programs use to store a family tree — the people, families, events, sources and photos that make up your research. GED Merge is a complete GEDCOM editor that runs entirely in your browser, so nothing is uploaded. Use it to edit your family tree, compare and merge a second file into it, and maintain the whole file with a suite of clean-up tools.

Part I — Getting Started

1What GED Merge is

GED Merge opens one or two GEDCOM files (the standard family-tree exchange format, .ged) and lets you work on them through three modes, switched from the tabs at the top:

  • Edit — browse and directly change your own tree: names, events, families, notes, sources and photos. No second file required.
  • Merge — load a second tree (or a matches CSV) and fold confirmed records into your own, field by field.
  • Tools — whole-file maintenance: a health check, duplicate finder, style normalizer, a privacy redactor, and source/place browsers.

Everything happens locally. Reading, matching, merging and editing all run inside your browser on your own computer, so your genealogical data never leaves your device. Your loaded file is never modified in place — you always download a new copy when you save (see §14).

Tip

New here? On the landing page, open one of the sample trees (Europe Royal Families, Tudors, US Presidents) to explore every feature with real data before loading your own file.

2The workspace

The app shell is the same in every mode. From the top bar you can:

  • Mode tabs — switch between Edit, Merge and Tools (shortcuts E M T).
  • File pills — the loaded main and incoming file names. Click a pill to see or replace that file.
  • Undo / Redo — one shared history across edits and merge decisions (CtrlZ / CtrlShiftZ).
  • Save GEDCOM — preview and download your changes (CtrlS).
  • Search everyone — the ⌕ button (or /) finds any person in the file by name; Enter opens them, ShiftEnter opens them in the tree.
  • Settings — the ⚙ menu holds appearance (theme and language), name and record display, and data options — see Settings below.
Note

The app is built for tablet and desktop screens. On a phone you can still review, but editing large trees is more comfortable on a wider display.

GED Merge is keyboard-driven — press ? anywhere to open the full shortcut sheet, or see §16.

Settings

The ⚙ Settings menu has two tabs. General covers everyday preferences; Advanced holds the one option that reaches the network. Every choice is remembered in this browser.

  • Appearance — Theme (Automatic, Light or Dark; Automatic follows your operating system) and Language (English or Slovenščina).
  • Names — Name order (given name first or surname first), Uppercase surnames (e.g. Ana NOVAK) and Show married surname, which appends it in parentheses, e.g. Ana Novak (Kovač). These change how names display everywhere; your stored data is untouched.
  • Display — Show record IDs puts each person's GEDCOM record id (xref) next to their name; Show kinship shows each person's relationship to your start person (§6) throughout the app.
  • Data — Remember my work in this browser (see Keeping your work below).
  • Advanced › Links — Look up link details online: when you add a source from a bare URL, GED Merge fetches its page title through a public relay. This is the only feature that sends anything off your device, and it is off by default.

Keeping your work & working offline

By default GED Merge keeps nothing between visits — reloading starts fresh. Turn on Settings › Data › Remember my work in this browser to cache your loaded files and your review and edit progress locally, so a reload restores exactly where you left off. The browser may ask permission to keep the data; nothing ever leaves your device. Clear saved data in the same panel empties that cache (the file you currently have open stays open).

GED Merge is an installable progressive web app. Use your browser's Install or Add to Home Screen action to run it in its own window; once loaded it works offline. When a new version is published, a small banner offers to Reload.

3Loading files

Drag a file onto the drop zone, or click to browse. The main file is your primary tree — load it first. In Merge mode you then load an incoming file: another .ged, or a matches CSV exported from indeks.rodoslovje.si (the Slovenian genealogical index).

After a file loads, the file-info panel reports what was read — individual and family counts, GEDCOM version, encoding, and the file's detected house style: its date format, place layout, source layout and name layout (explained in §7). For an incoming file it also lists how many dates, places, links and names were reshaped to match your main file, and how many split copies of the same person were merged into one.

Tip

If your tree references local photos, GED Merge offers to connect a media folder so it can display them. See §12.

Part II — Core Concepts

4Main file & Incoming

The main file is your primary family tree — the one you own and maintain. The Incoming file is what you compare against it: a second GEDCOM, or a matches CSV from indeks.rodoslovje.si. Edits and merges only ever build a new copy for download; your originals on disk stay untouched.

5The match score

When both files are loaded, GED Merge automatically pairs individuals between them and gives each pair a match score from 0 to 100%. The score weighs several signals: surname, given name, birth and death date and place, parents, partners, children and marriage. Implausible pairs are filtered out early (for example, an irreconcilable surname or an impossible age gap), so the list surfaces genuine candidates.

A high score means the two records are very likely the same person; a middling score is worth a careful look. The Find duplicates tool uses the very same engine to spot two records inside one file that describe the same person.

6Start person & kinship

Set a start person — usually yourself or the root of your tree — and GED Merge ranks matches by kinship distance: how many relationship hops separate each candidate from your start person. Your closest relatives then surface first, and each match shows its relationship (e.g. Grandfather, 2nd cousin). A sensible start person is chosen automatically when a file loads; you can change or clear it at any time. Go to start person jumps the current view back to them at any moment.

Kinship labels are colour-coded by blood line: relatives on the father's side show in blue, the mother's side in purple-magenta, while full siblings (“both lines”), descendants and the start person keep the neutral green accent. When two people share a bloodline but no single named kinship fits, a generic Blood relative label carries the colour. Kinship also recognizes half-siblings and step-relations (step-parent, step-child, step-sibling) with their own labels. The colours appear wherever kinship shows — person headers, relative cards, tree nodes and the relationship diagram (see the legend, §15).

7House style & normalization

Every GEDCOM has its own conventions — its house style. GED Merge detects four of them:

  • Date format — e.g. 01.01.1900 vs 1 JAN 1900, including how unknown parts are marked.
  • Place layout — whether places are one packed line, a structured comma hierarchy, a separate street address, and so on.
  • Source layout — bibliographic citations, repository links, page-image sources (Matricula-style), or inline text.
  • Name layout — whether alternate names live as inline sub-tags or as separate typed name records.

When you load an incoming file, GED Merge normalizes it to your main file's house style before comparing — reformatting its dates, reshaping its places, rewriting links (Matricula, Geneanet) and reshaping name variants — so the comparison is like-for-like and anything you merge in already matches your file's conventions. The Normalize tool applies the same idea within a single file, bringing outliers in line with the file's own dominant style.

8Sources, media & lossless data

GED Merge reads the whole file losslessly: every line is preserved, including custom and non-standard tags, so nothing is silently dropped when you save. Beyond people and families, that includes sources (repositories, source records and citations), media objects (photos and document images), and the notes and links attached to any record. These are first-class throughout: you can add and edit them in Edit (§13, §12) and browse them across the whole file in Tools.

Part III — The Three Modes

9Edit — your main GEDCOM file

Navigating

Switch to Edit (E) to browse and modify your main file directly — no second file needed. Pick anyone from the Jump to person box, or click a relative's card to walk the tree; Back returns to where you came from. If the current person also matches your incoming file, Merge in the toolbar jumps straight to that comparison. Every change is held in memory and reversible with CtrlZ until you download.

Charts hub

One Charts button (V) — in the Edit toolbar, the header's chart icon, or a Compare Tree node's panel — opens the full-page Charts hub for the selected person. A tab strip switches between seven kinds (digits 1–7 jump straight to one); GED Merge remembers whichever you used last:

  • Tree, Grid, Fan and Circle — the four pedigree styles. Tree is the tidy layered family tree; Grid aligns generations into columns (a pedigree grid for ancestors, an indented outline for descendants); Fan and Circle are radial ancestor charts (ancestors only — there's no descendants view to fan out).
  • Timeline — the immediate family as lifespan bars along one shared year axis; see below.
  • Relationship (S) — traces how the selected person is related to your start person (§6); if none is set yet, it prompts for one inline. The diagram lays out the chain of relatives between the two, labelled with the exact kinship (e.g. 2nd cousin once removed). When more than one route exists, the Available paths menu switches between the shortest path and a bloodline through a shared ancestor. Click either endpoint's ✎ to swap that person, click any node to re-centre, or open a node in Edit.
  • Report — a text-based Ahnentafel or descendant register; see below.

The pedigree kinds and the Report also carry an Ancestors / Descendants toggle (each option shows a live count). The Chart button (the ⚙ gear) opens a settings panel whose options adapt to whichever kind is open; every choice is remembered across sessions:

  • Alignment (Tree only) — lay the tree out Left → Right or Top → Bottom.
  • Person — toggle what each node shows: Lifespan, Place, Photo (when a media folder is loaded), Kinship (the relationship label to your start person; not drawn on Fan/Circle) and Badges (the working-state letters — see §15 — on by default). This group isn't shown while the Report is open; switch to another kind to change it, and the Report picks up whatever it's set to.
  • Marriage — add the marriage Date and/or Place to each couple's connector (the fan / circle collar, or beside the Timeline's ⚭ markers). Both off by default.
  • Events (Timeline only) — whose bars carry event dots: This person, All people or Off; plus Event labels (compact text under each dot) and the shared Residence bar (see Reports, below).
  • Facts (Report only) — see below.
  • Privacy — Hide living people redacts anyone inferred to be living, showing only their relationship or “Living” (see §19), so the diagram is safe to share.

Use the zoom controls to zoom in and out, reset to 100%, or fit the whole diagram to the screen; large diagrams also show an overview minimap — drag the canvas to pan. Every kind carries an Export ▾ menu: GEDCOM (first — downloads just the people currently drawn as a standalone file a friend can merge into their own tree), SVG (a sharp, infinitely scalable image) and PDF (opens your browser's print dialog, where you choose Save as PDF). The Report adds a Text file option instead of SVG.

Timeline

The Timeline kind draws the selected person's immediate family as horizontal lifespan bars on one shared year axis: parents (and a step-parent row, if one remarried) above, the person's own generation — siblings and half-siblings interleaved by birth order — beside them, then each union's spouse and children (and step-children) below. Small glyphs mark dated events on each bar (* born, ~ baptized, † died, ▭ buried, ⌂ residence, ⚒ occupation, ✎ education, →/← emigration/immigration), and ⚭ marks a marriage. An open-ended bar (no death recorded) tapers off — to the last dated event, or to the present day if the person is presumed living.

Reports

The Report kind renders a text-based, numbered report instead of a diagram — the same Ancestors / Descendants toggle as the pedigree charts switches between two classic genealogical formats:

  • Ahnentafel (Ancestors) — the standard ancestor numbering: the root person is no. 1, their father 2n, their mother 2n+1, grouped by generation. A generation's heading shows its entry-number range and how many of its ancestors are actually known (e.g. 3 of 4 known). A person who appears twice through a shared ancestor (pedigree collapse) shows once in full, with later appearances as a clickable “→ same as no. X” link back to the original.
  • Descendant register (NGSQ) (Descendants) — sequential numbering in the order each person appears; every generation groups children under a clickable “Children of NAME and SPOUSE” heading that jumps back to the parents' entry.

A second toggle switches the writing style:

  • List — compact numbered fact lines (the Timeline's glyph vocabulary).
  • Narrative — the same facts as flowing prose paragraphs, book-style, written in your interface language. Sentences use the correct tense for people presumed still living, and Slovenian narrative correctly declines dates and pronouns (place names are never inflected). Sources become numbered footnote markers on the sentence they support; short notes are woven in parenthetically, longer ones become their own footnote.

The Facts group in Chart settings adds optional lines (or narrative sentences) per person: Occupation, Education, Residence (shared with the Timeline's Residence bar), Notes and Sources (with a link to the cited page or image, where one resolves). Click any entry to open its detail panel, re-root the report on that person, or jump to Edit. Export GEDCOM (everyone currently listed), a plain Text file, or PDF — all three carry the same headings, numbering and facts as the page.

Names & identity

Given name, surname, sex and nickname edit inline — click a field, type, click away to save. The × glyph clears a field. + Add Name attaches alternative name variants (married name, name at birth, aka, formal and more), each with its own given name, surname and type; the − glyph removes a variant.

Events

Birth shows by default. + Add Event reveals the rest, grouped by life stage:
  • Early Life — Baptism, Christening, Confirmation, Adoption, First Communion
  • Career — Occupation, Education, Retirement
  • Residence & Movement — Residence, Emigration, Immigration, Naturalization, Census
  • Estate — Will, Probate
  • Death — Death, Burial, Cremation
Each event row carries date, place and address; expand it to add a note, agency, type, cause and sources. Use × to clear a single field. To change an event's type or remove the whole event, use the dropdown menu on its event-type label.

Family relationships

The panel shows three family sections:
  • Parents — + Add Father / + Add Mother search for an existing person or add a new one. The − glyph detaches the role without deleting the record.
  • Partners — + Add Partner creates a spouse family. Each shows the marriage event and supports Engagement, Separation and Divorce via + Add Family Event; − detaches the spouse. Families carry their own notes and links too.
  • Children — listed under each spouse family. + Add Child adds an existing or new person; − unlinks a child without deleting them.

Notes, sources & photos

Individuals and families can carry free-text notes, sources and photos. + Add Note and + Add Source reveal their inputs (the Add Source dialog is covered in §13); once a link is present the ↗ glyph opens it in a new tab. Adding and captioning photos is covered in §12.

Detach vs delete

Detach (the − glyph) only removes a family connection — both individual records survive and can be re-linked later. Delete Person (the 🗑 at the foot of the panel) permanently removes the individual and unlinks them everywhere.

Cannot be undone

Deleting a person is permanent and asks for confirmation. If in doubt, download a backup copy first.

Saving

Save GEDCOM opens a preview of exactly what changed, then downloads the edited file — see §14. Your loaded file is never modified.

10Merge — compare & combine

The match list

With both files loaded, the Matches list shows every candidate pair with its score and — if a start person is set — its relationship distance. Selecting a row opens the side-by-side comparison. Step through with ← / →.

Filtering

The filter button (top-right of the panel) shows or hides the filter controls, and the header reports how many candidates pass them (e.g. 74 of 114). Narrow the list with:

  • ≥ score — a minimum match-score threshold
  • New persons — only matches that could bring in new ancestors or descendants
  • New data — only matches that add new field data
  • New links — only matches that add or change attached links
  • Differences — only matches with conflicting fields
  • Search name — filter by given name or surname

Columns & sorting

Each row shows the candidate's name and life span, then a set of count columns. Every column header is also a sort button — click it to sort by that column, click again to reverse.

ColumnWhat it shows
ScoreThe match score, 0–100.
DistanceKinship hops from your start person — shown only when a start person is set.
New personsIncoming-only ancestors and descendants this match could bring in. Confirming the merge doesn't import them — choose which to bring in from the Compare Tree.
New dataNew fields the incoming file would add.
New linksAttached links the incoming adds or that differ.
DifferencesFields present in both files but differing.
StatusYour decision — confirmed, rejected or deferred (round status badge; see §15).

Comparing & resolving conflicts

The compare panel highlights only fields that add new data or conflict. For each conflicting field, choose which value to keep:

  • M — keep the Main file's value
  • I — take the Incoming value
  • B — keep Both

Marking each match

Give every pair a decision, by button or shortcut: C Confirm (C), R Reject (R), or D Defer to decide later (D). Only confirmed matches are merged on save.

Compare Tree

Compare Tree (V) shows a matched person's ancestors and descendants from both files in one diagram, so you can be sure they're really the same person. Nodes are colour-coded: match, minor differences, major differences, main file only, incoming only. From here you can re-root on any person, mark a status, or use + Bring ancestors / + Bring descendants to graft a whole incoming branch into your main file on save. The Chart settings, zoom controls, overview minimap and Export ▾ menu all work here just like the other diagrams (see §9) — except there's no GEDCOM export, since a compare tree can include incoming-only people not yet in your main file.

Merging

Save GEDCOM previews every confirmed match and edit, then downloads the merged file — applying your field-level choices to a copy of the main file and pulling in any new individuals and families connected to those confirmed matches. Full detail in §14.

11Tools — whole-file maintenance

The Tools tab (T) runs checks and clean-ups across your entire main file. Each tool works in the browser and previews its result before you download; your live file is untouched until you do.

Health check

Scans every individual and family for data problems and groups them by category: no name, no sex, no vital dates, disconnected records, broken or one-way family links, duplicate pointers, pedigree loops (a person who is their own ancestor), sex vs. role conflicts (a female recorded as a husband, or a male as a wife), future-dated events, death before birth, and implausible ages (at death, at marriage, parent's age, spouse age gap). A separate GEDCOM structure pass flags encoding, bad lines and levels, stray CONT/CONC, version, unknown or custom tags and unparseable dates — many with a one-click Fix. When a media folder is connected, Check media folder lists referenced media files that are missing from it.

Click any issue to open the record in Edit. Batch fixes handle the common cases in one step: Fix all broken links clears dead and one-way family pointers, Remove duplicate pointers de-duplicates repeated links, and a sex fix sets the sex on unspecified spouses (husband → male, wife → female).

Find duplicates

Compares every person against every other using the same engine as Merge, and lists likely duplicate pairs with their score. Expand a pair for a side-by-side comparison, then Merge to keep the surviving record and fold the other into it — family links are re-pointed automatically, and the action is undoable.

Normalize

Detects the file's own dominant date format, place layout and link style, then re-renders records that deviate — e.g. 1 Jan 1900 → 01.01.1900, reshaping places, and rewriting Matricula or Geneanet links to a consistent form. A preview lists examples of each change before you download the normalized copy.

Privacy

Produces a redacted copy of your file for sharing or publishing, with living people protected — your live main file is never touched. GED Merge infers who is likely living: anyone with no death, burial or cremation event whose estimated birth is recent enough. The estimate comes from their own birth year, or — when that's missing — from dated relatives, or finally a configurable assume-living fallback. A breakdown shows how many were flagged by birth date, by relatives, or assumed.

You control what happens to each flagged person:
  • What to do — sanitize them in place, remove the person, or remove the person and all descendants.
  • Replace each name — with “Living”, custom text, initials, initial + surname, or surname only.
  • Also remove from each flagged record — dates & places (all events), notes, sources, photos & media, or contact details.
  • GEDCOM restriction — strip the data and mark a RESN privacy tag, strip only, or mark only.
  • Also privatize people who died within a chosen number of recent years.

File-level options strip data that isn't tied to one person: the submitter record (your own name, address and email), external tree ids (_UID, _FID, AFN), and every postal address, email or phone number across the whole file. A preview counts how many people are redacted or removed before you download the redacted GEDCOM.

Sources

Browse every repository, source record and media object, grouped by repository. Selecting one shows which individuals and families cite it, each a link into Edit; unattached media and link-only citations are listed separately. A Potential duplicates view groups records that describe the same media, source or repository under different ids — pick groups to collapse and download a deduplicated file with every citation re-pointed.

Places

Lists every place in a country → locality → house → address hierarchy, with a usage count per place. Open a place to see the records that use it, or use Rename on any level to bulk-rename or merge a place segment across every record at once — ideal for standardizing spelling variants.

Part IV — Shared Features

12Photos & media

GEDCOM files reference image files by name rather than embedding them, so to display photos GED Merge needs the folder they live in. Connect a media folder from the file-info panel (or accept the prompt offered when a file references local images). The folder is read locally — your photos never leave your device.

Viewing

Click any thumbnail to open the full-screen lightbox. When a person has several photos, step through them with ‹ / ›, the arrow keys, or the thumbnail tray; Esc closes. For a shared media object the info panel also lists the records that reference it, each a link into Edit. When a photo records a marked region for this person (a crop within a group photo), GED Merge highlights that area so you can tell who is who.

Adding & editing

In Edit, Add media attaches an image from your media folder (Chrome and Edge can also accept a file dragged in). In the lightbox, the info panel is editable: change a photo's title, date (the date the image depicts), place and description — each field saves on blur and joins the normal undo/redo history. The × control removes a photo from the person; the image file on disk is kept.

Note

Media folders need a modern browser (Chrome, Edge or Firefox). Firefox shows a generic “upload” warning when you pick a folder — nothing is uploaded; the prompt is just how the browser asks for folder access.

13Sources & citations

+ Add Source — on a person, a family, or an individual event — opens the Add Source dialog. Paste a full citation or just a URL: GED Merge fetches the page title where it can, and detects when your citation matches an existing source in the file, adding the new page to it rather than creating a duplicate. You can fill in structured fields — title, author, periodical/series, publisher, agency, filing number, page, URL and note — as needed for your house style.

Existing citations can be reopened and edited the same way. To see and tidy sources across the entire file — including duplicates — use Tools › Sources (§11).

14Saving & the change report

Looking for the Ahnentafel or descendant-register report? That's the Charts hub's Report kind (§9) — this section covers saving your file and its change log.

Saving is one unified flow for both edits and merges. Save GEDCOM (CtrlS) opens a preview listing every change — persons and families changed, fields applied, new records added, and anything that could not be merged. Each entry carries a badge: New, Incoming, Edited or Removed. Use Remove from Save to drop any single change before downloading.

Download GEDCOM writes two files: the new .ged and a plain-text change report documenting exactly what was applied. The downloaded file becomes your new working baseline inside the app, so what you see next matches what you just saved.

Tip

Your original file on disk is never overwritten — the download is always a new copy. Even so, keep a backup of your tree before large merges.

17Event types

Events you can add to a person, grouped by life stage (families add Engagement, Marriage, Separation and Divorce):

  • Birth — always available
  • Early Life — Baptism, Christening, Confirmation, Adoption, First Communion
  • Career — Occupation, Education, Retirement
  • Residence & Movement — Residence, Emigration, Immigration, Naturalization, Census

18Glossary

IncomingThe file you compare against the main file: another GEDCOM or a indeks.rodoslovje.si CSV.

19Privacy

All reading, matching, merging and editing happens locally in your browser, on your own computer — including your media folder, which is read on your device only. Your family tree is never sent to a server. The full Privacy Policy & Terms are also linked in the footer below.
