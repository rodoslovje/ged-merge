Changelog

What's new in GED Merge, newest first. Only user-facing changes are listed here.

2026-07-13

  • Photos from other programs now display better: a primary photo flag (MyHeritage/Legacy/RootsMagic _PRIM, webtrees _THUM) makes that photo the person's thumbnail and first in the tray, Family Historian's _SEQ ordering and _KEYS keywords are honored, and MyHeritage face crops (_POSITION) show like GEDCOM 7 crop regions.
  • Cleaner outputs: MyHeritage's _UPD timestamps become standard change records (CHAN) on load; the save preview explains each custom tag and pre-deselects the purely software-internal ones; and Tools → Normalize gains an opt-in Remove internal software tags pass (_UPD, _RINS, _COLOR, flags …).
  • When the incoming file uses a different GEDCOM version than your main file (5.5.1 vs 7.0), it is now migrated to the main file's version on load — shared notes (NOTE ⇄ SNOTE), date phrases and interpreted/dual-year dates, age keywords, association roles, legacy identifiers (AFN/RFN/RIN ⇄ EXID), transliterated names and media types are all rewritten to the main file's spec, so merged records stay valid. The load summary shows what was migrated, with examples on hover.
  • More reliable undo bookkeeping: undoing an edit on a newly added person, or on a shared media record's details, no longer confuses the pending-changes count; adding a relative now also lists the affected family in the save preview; and undoing a deleted person restores them at their original position in the file.
  • Marking a pair as Not a duplicate in Tools can now be undone with the regular Undo/Redo.
  • The save preview now warns when a confirmed match no longer applies cleanly — the person was deleted, or edited after the match was confirmed — so stale field choices don't overwrite newer edits unnoticed.
  • Better support for other genealogy programs' GEDCOM files: person attributes that used to be invisible — reference numbers (REFN), titles, religion, nationality, physical description, number of children, graduation and generic facts — plus Brother's Keeper's funeral, interment, military-service and medical entries now show up in Edit mode and in merge comparisons, can be edited and added, and merge like any other event. Generic "Event"/"Fact" rows now show their type in the heading (e.g. Event — FamilySearch ID).
  • The Health check now explains the custom tags other programs leave in a file — e.g. _UPD (160×) — MyHeritage: last-updated timestamp — instead of only listing them, covering the tags of Brother's Keeper, Family Historian, MyHeritage, Family Tree Maker/Ancestry, Legacy, RootsMagic, MacFamilyTree, webtrees, Gramps and PAF.
  • Privacy tool: Remove submitter now also strips account traces other programs embed — MyHeritage site-publish records (with your account e-mail), Ancestry account tokens and webtrees editor names; the external-id strip also covers FamilySearch, Ancestry and Find a Grave ids.
  • Normalization (on compare-file load and in Tools → Normalize) gains a vendor tags pass: Brother's Keeper's _SEPR becomes the standard Separation event and its older _MILI military tag becomes _MILT; the incompatible "unmarried partners" encodings (Brother's Keeper's never-married trio, MyHeritage relationship events, Family Tree Maker's _STAT) are consolidated into one family Status field; and agreeing _FREL/_MREL child relationships become the standard PEDI (adopted/foster), with the default "Natural" pairs removed as noise.
  • A family's partnership Status ("Partners", "Divorced" …) now shows in merge comparisons and in Edit mode's family section, where it can be added, edited and merged like any other family event.
  • Matching now recognizes record identifiers (_UID, GEDCOM 7 UID — written by MyHeritage, Family Historian, Legacy, Gramps, RootsMagic, PAF …) and FamilySearch person ids (MacFamilyTree's _FID, RootsMagic's _FSFTID): two records carrying the same id are matched with certainty (🔑, score 100) even when names or dates have diverged — across programs, too — and merging carries the incoming id onto your record so the next import of the same file matches instantly.
  • MacFamilyTree's bare vendor tags are now recognized: the Health check explains them instead of flagging them as unknown, the periodical name PERI is treated as standard, MISE is normalized to the Military service event, a second given name (SECG) that's missing from the main name is folded in, and RACE, awards (NOBI), legal transactions (LATR), deeds (DEED) and illnesses (ILL) show as editable, mergeable facts.
  • The Health check now reads the field tags a MacFamilyTree file's own source templates declare (cemetery, census year, county, microfilm roll number …), so those bare tags (CEME, CENY, COUN, LOCA, ROLN, TOWN …) are explained as template fields instead of flagged as unknown.
  • Tools → Normalize no longer rewrites tags that are the file's own program's dialect: a MacFamilyTree file keeps its native MISE military-service tag (and a Brother's Keeper file its _SEPR) instead of gaining a spelling its own program wouldn't recognize on re-import. Loading a compare file still converts these tags as before.

2026-07-12

  • The Tools scans (Health check, Find duplicates, Normalize, Sources) now run in the background — the app stays responsive while a large file is scanned, instead of freezing until the scan finishes. Finished results are kept while you switch tabs or modes, and a scan keeps running if you browse elsewhere in the meantime.
  • The duplicate scan shows its progress and can be cancelled. On files with a huge number of pairs the list shows the highest-scoring ones, so browsing and opening a pair stays fast — use the search box to reach the rest.
  • Tidier + Add menu in Edit mode: Place, Address and Agency now come before Source, the source entry reads simply Source, and the media button is labelled Add Media.
  • New Age option under a chart's Person settings: each person's age (at death, or current for the living) shows in parentheses after their lifespan — or, when the lifespan is turned off, as its own "age N" line. It appears on the node boxes and in the chart title, works on the tree, pedigree, fan, relationship and timeline charts, and starts on automatically when the global Show ages preference is on.
  • New Age option under a report's Facts settings: the age reached shows in parentheses next to each fact's date — the person's own age on their events, both spouses' ages (♂ / ♀) on a marriage, and the parents' ages on a birth. In the narrative style it reads "(age N)" / "(star/stara N let)".
  • Search now ignores accents: typing Ziva finds Živa, Skofja finds Škofja — so names and places aren't missed when čšž and similar letters are typed plainly. Applies to the whole-file search and every person picker.
  • Safer saving of imperfect GEDCOM files: when two records share the same ID, only the surviving record is written (previously both copies ended up in the saved file); text that starts with @ is saved with the standard doubled @@ escape so other programs don't misread it as a record reference; a / typed into a name field no longer corrupts the saved name line; and a line with a skipped level in a damaged file now stays inside its record instead of being detached from it.
  • If background processing (loading, matching or a Tools scan) fails unexpectedly, the app now reports the error instead of spinning forever.

2026-07-11

  • Much more compact Edit mode: each event now fits on a single line — the date, place and any other filled-in fields flow together and wrap only when needed, instead of taking three rows. A hover-only + Add menu adds a source, place, note or other detail on demand, so empty fields no longer clutter the view.
  • Full keyboard editing: Tab through every field, and press Enter on the event-type ▾, the Sex picker or the + Add menu to open it; the field you add is focused for typing, and closing the Add Source dialog returns you where you were.
  • Person sources and notes are more compact too, and newly added or changed notes now show in bold like other edited data.
  • Merge mode now respects the Show ages display setting, just like Edit mode: the person's age appears next to the lifespan in the matches list and the compare panel header, next to each relative (parents, partners, children) in the compare table, and after each event date — the person's own age, the parents' ages on a birth, and both spouses' ages on marriage and other family events.
  • When Show ages is on, the photo viewer now shows how old a person was when a dated photo was taken — in the "Date depicted" line, and, for group photos, next to each tagged person on their hover box and in the "referenced by" list.

2026-07-10

  • Tools → Find Duplicates now has a Reject action to mark a pair as not-a-duplicate; rejected pairs are remembered so they won't resurface next time you run the scan, and can be reviewed and un-rejected from a new "Rejected" list.
  • Rejecting a match in Merge now hides it from the list right away, and the compare panel auto-advances to the next candidate.
  • The footer now shows the app version, linking to this changelog — also available in Slovenian at /posodobitve.
  • New Verify button on a loaded GEDCOM file (Chrome/Edge): checks whether the file has changed on disk since it was loaded and offers to reload it, with an automatic check on page reload where possible — always confirming first if you have unsaved changes.

2026-07-08

  • Fixed a bug where the PDF / print export of a chart could come out blank.
  • The relationship diagram now prefers a path through a shared ancestor over an arbitrary same-length route.

2026-07-13

  • Long lists stay fast on very large files: match results, Health check findings and duplicate pairs now render only the rows on screen while scrolling through the full list.
  • The duplicate finder no longer stops at the 200 highest-scoring pairs — every found pair can be scrolled to and reviewed.
  • Editing stays snappy on complex persons and very large files: committing a field no longer re-renders the whole person layout, and adding people or sources no longer rescans every record.
  • Fixed: removing a source's last citation could delete its page image even when that photo was still attached to a person, leaving a broken reference.

2026-07-07

  • More reliable "living person" detection: when someone has no birth date of their own, GED Merge now also looks at dated relatives before assuming they're living.

2026-07-06

  • New Settings → Display → Show ages toggle: ages next to lifespans and event dates, plus a full year/month/day breakdown in tooltips.
  • Photos are now called media everywhere, with support for SVG and PDF files, dragging files straight into your media folder, and marking a person's region on a group photo to use as their thumbnail.
  • Reports gained an RTF export, an optional table of contents, and living-person redaction.
  • Added support for GEDCOM files exported from MyHeritage.

2026-07-04

  • New Report chart kind: an Ahnentafel ancestor report and an NGSQ-style descendant register, each available as a compact list or as flowing narrative prose — in English and Slovenian.
  • The Charts hub now brings Tree, Grid, Fan, Circle, Timeline, Relationship and Report together under one tab strip, with a shared GEDCOM / SVG / PDF export menu.

2026-07-01

  • GED Merge is now an installable, fully offline-capable app (PWA).
  • Optional local persistence: turn it on and a reload restores your loaded files and progress.
  • Added global search across the whole file.

2026-06-30

  • Set a start person and see everyone ranked by kinship distance, colour-coded by paternal or maternal line.

2026-06-29

  • Health check now flags pedigree loops (a person who is their own ancestor) and sex/role mismatches.

2026-06-28

  • Added Grid, Fan and Circle chart types alongside the family tree.

2026-06-27

  • Added the relationship diagram, and a Privacy tool that redacts living people before you share a file.
  • Any chart can now be exported as SVG or PDF.
